# E4.7 FROZEN

E4.7 is E4.6 (`planpath46/`, tag `e4.6-frozen`) with the per-clip DECISION calls thinking OFF by default. Decision (founder, 2026-10-08), on the measurement in `memory/2026-10-08-decisions-thinking-off.md`: on gold3b (195 units, 1,937 scorable questions) Swift 1.5 with thinking off is 0.6 points below thinking 2048 (paired, McNemar p = 0.48) and about 4.7 times faster per call (2.9 s against 13.8 s); thinking 1024 is worse than both. `planpath46/` and every older directory are untouched: E4.7 lives in `planpath47/`, a copy of `planpath46/` in which EVERYTHING else is byte for byte E4.6 (the test `test/e47.test.mjs` compares every file). Verify: `node planpath47/verify-frozen.mjs` (exit 1 if any listed file changed); git tag `e4.7-frozen`. The E4.6 record (`E4.6-FROZEN.md`) stays here as history; the E4.5 DSPy tuning is still not part of the freeze, and no new test set was authored.

## What changed (and nothing else)

1. **`transport.mjs` (new).** E4.6's request builder (`hybrid3/lib.mjs buildRequest`, frozen and untouched) wrapped:
   - **Decision calls (`kind: 'decision'`) think off by default.** `E4_DECISION_THINKING=off | <budget in tokens>`; unset means off; a budget is raised to 1024 (ninfer's minimum; 512 is rejected by the server) and anything else that is not a number throws.
     | wire (`E4_LLM_API_STYLE`) | thinking off | thinking with a budget N |
     | --- | --- | --- |
     | `ninfer-messages` | `"thinking": {"type": "disabled"}`. The field is never omitted: without it the model thinks (279 tokens on the probe). Verified on the lane: 0 thinking tokens | `{"type": "enabled", "budget_tokens": N}` (what E4.6 sent) |
     | `llama-chat` (new) | `"chat_template_kwargs": {"enable_thinking": false}`. A top-level `enable_thinking` returned an EMPTY message (1 token): not used | top-level `reasoning_budget_tokens` N and `reasoning_budget_message` (`E4_LLM_BUDGET_MESSAGE`, default "Time to stop thinking. Give the final answer now.") |
     | `openrouter` (GLM and the like) | `"reasoning": {"enabled": false}`, OpenRouter's reasoning switch (a model that cannot be switched off ignores it). **Not exercised against a model** (no remote model is used here); only the request is tested | `"reasoning": {"max_tokens": N}` (what E4.6 sent, with N = 4096) |
   - **The wire `llama-chat`** (llama.cpp and Strata): `POST <E4_LLM_URL>/v1/chat/completions`, no key, `max_tokens` and `temperature` of the call, and the thinking fields above. Other call kinds get their usual per-kind budget (`E4_LLM_BUDGET_<KIND>`, else `E4_LLM_BUDGET`, else the settings' 4096, minimum 1024) as `reasoning_budget_tokens`.
   - **`E4_LLM_MAX_TOKENS`** caps `max_tokens` of every call to what the server's context slot holds. Unset: no cap (E4.6's 32000 / 16000).
   - Planner, bible, writer, repair and reference-writer calls on `ninfer-messages` and `openrouter` build EXACTLY E4.6's request (tested over all call kinds, byte for byte).
2. **`lib.mjs`.** `buildRequest` comes from `./transport.mjs`; `chat()` (the hybrid repair's call, E4.6 took it from `hybrid3/lib.mjs`, whose own `buildRequest` knows only two wires) is defined here, line for line the hybrid3 function, on the E4.7 transport; `HERE` is `dirname(fileURLToPath(import.meta.url))` (`URL.pathname` is `/C:/...` on Windows); the dhee-core `.env` read is optional (a local endpoint needs no key).
3. **`hybrid46/repair.mjs`.** One import line: `chat` from `../lib.mjs`.
4. **Scripts.** `freeze.mjs`, `verify-frozen.mjs` default to this record; `replay-check.mjs` takes `--style`, `--model`, `--env K=V` and reads a decision request with `thinking {type: disabled}` (or `reasoning {enabled: false}`) as the stored decision request it corresponds to, counting it.

The decision PROMPTS, the option lists, the schema, the retries and every check are untouched: with thinking off the same question is asked of the same model, in the same words.

## Proof that nothing else changed (`test/e47.test.mjs`, 14 tests; the 91 E4.6 tests pass unchanged in `planpath47/test/`)
- **Transport, byte for byte:** over the call kinds planner, bible, writer, repair, refrepair, refwriter, on `openrouter` and on `ninfer-messages`, E4.7's request equals `hybrid3`'s (`JSON.stringify` equal). A decision request on `ninfer-messages` differs from E4.6's only in the `thinking` object (same keys in the same order); with `E4_DECISION_THINKING` = E4.6's budget (1024, 2048, 4096) it is E4.6's request, byte for byte. On `openrouter` the same holds with 4096.
- **Files:** every file of `planpath46/` that exists in `planpath47/` and is not listed above is byte-identical (the test reads both), and `planpath47/` adds only `transport.mjs`, `E4.7-FROZEN.md` and `test/e47.test.mjs`. `lib.mjs` differs from E4.6's in exactly the three removed lines and the added lines named above.
- **Replay on a stored real run** (`results/2026-10-08-e4.6-horror`, Swift 1.5 on the ninfer lane, 14 requests: planner 2, bible 1, ref repair 2, decisions 3, writers 3, repairs 3), `node planpath47/replay-check.mjs results/2026-10-08-e4.6-horror results/2026-10-08-e4.6-horror --stories horror --style ninfer-messages --model swift-1.5-qwen3.8-27b-orcarouter --env E4_SCORE=on [--env E4_DECISION_THINKING=2048]`: a local mock serves the stored replies by the exact request body and every request that is not a stored one counts as a mismatch.
  - With `E4_DECISION_THINKING=2048` (the stored decision budget): **14 of 14 stored requests made, 0 mismatches, 6 of 6 stored output files identical** (plan, bible, fix, shots, dialogue ledger, staging ledger), 3 of 3 exported prompts identical. E4.7 is E4.6, request for request.
  - Default (decisions off): **14 of 14, 0 mismatches**, 3 decision requests read through their `thinking {disabled}` (every other byte equals the stored request), the same 6 of 6 files and 3 of 3 prompts. This holds because the stored replies are served whatever the thinking; it proves the REQUESTS are the same, not that a model answers a thinking-off request as it answered the thinking-on one (that is the measurement above).

# Changelog

## Unreleased

- **Sparse attention recipe inputs**: `sparse_start_percent` (FLOAT, default -1 = auto), `sparse_dense_blocks` (STRING, default `auto`) and `sparse_sink` (`auto` / `exact_kv_and_rows` / `exact_kv` / `off`, default `auto`) expose the three values that were fixed in core BlockSparseAttention's call (start 0.20, no dense blocks, `exact_kv_and_rows`). Appended after every existing widget. `auto` resolves to HyperFlow's validated recipe (start 0.16, dense blocks `0,1`, sink off) only with HyperFlow 8-step + `sparse_method` sol-attn; everywhere else it is the old fixed values, so old workflows and non-HyperFlow / sla / vsa runs render as before. Any value you set wins in every mode. `sparse_tau` is unchanged (default 1.3; HyperFlow's recipe is 1.0, noted in its tooltip). The HyperFlow log line now prints what is in effect (tau only for sol-attn, keep % for sla / vsa, start, dense_blocks, sink and where each came from) and the sparse success log includes dense_blocks and sink. Saved workflows load with auto (the old trailing `master_ui` value that lands in `sparse_start_percent` is reset to -1); example workflows updated; the Metadata performance line shows the new fields.
- **One call per clip, with the reference pictures in context** (supersedes the caption step of the entries below): a rewriter model that can see no longer captions the pictures first. The story planner and every clip's writer call get the pictures themselves (up to 9) as image parts, together with the story, the ask and the continuity blocks. Pictures are downscaled once to at most 896 px on the long side (a multiple of 28; at most 1,024 tokens each, 9,216 for nine) and go FIRST in the user message as `Picture 1:` + image ... `Picture N:` + image, in a fixed order and byte-identical in every call; the system prompt is identical in every call too (its continuity / story / reference / state rules are chosen per run, not per clip), so a server that caches the prompt prefix reads the pictures once. A picture is no longer described anywhere: the `Identity:` / `Outfit shown:` caption and its cache entries are gone for pictures (the wardrobe rules are kept, reworded to point at the attached pictures: identity from the picture, wardrobe from the ask, the previous end state and the story, `partially_preserved` when the outfit changes, the picture's own outfit never described). Reference videos are still captioned on a llama/ninfer session. `planner_refs=captions` is now the same as `images` (no input changed, so saved workflows load as before). A ninfer vision tower now also takes pictures in the chat call (before, the planner only had its captions). Strata sees too: vision detection is the gateway config having `--vision` in `args` and a `vision` entry whose files exist, or, for a Strata already running, its `/v1/models` input modalities; otherwise Strata takes the no-vision path as before. Strata requests carry the pictures as OpenAI `image_url` data URIs next to `reasoning_budget_tokens`; `max_tokens` is still the budget plus the answer; the usage from its final chunk is logged. One log line per run gives the picture count, the sent sizes and the estimated image tokens. Tests use stubbed servers (9-reference clips, no caption call for a vision writer, downscaling, the Strata body, the no-vision fallback, the planner's pictures).
- **One rewriter model**: `rewrite_caption_model` is removed (node and Studio panel); `rewrite_writer_model` now both captions and writes. A model with vision (the pack lists it as a captioner, i.e. it has an mmproj) captions the references, feeds `planner_refs=images` and writes on one server session, with no second load. A model without vision (Strata, or a GGUF with no mmproj) skips the image interpretation: no captions, no image input, text-only rewrite, one log line (`writer has no vision: reference images not interpreted`). The Ref2VA picture labels are kept as `Picture N: an attached reference picture (not described here)` plus a rule not to guess what a picture shows; the planner gets the story text alone. Removing a widget shifts the saved widget values, so `web/widget_migration.js` drops the old caption value on load (recognised by the caption length sitting two slots after the writer) and the later values stay in place; the old value is discarded. The example workflows are updated. Strata requests are unchanged; the caption model's server is no longer opened before Strata starts.
- **Thinking budget dropdown**: `rewrite_reasoning_budget` is now a combo `1024` / `2048` / `4096` (default `4096`) instead of an INT. Old workflows, saved projects and API graphs that send another number are mapped to the nearest allowed value (`-1`/`0` and anything above 4096 give 4096) in the panel (on load) and on the server (`VALIDATE_INPUTS` skips the combo check so a numeric `4096` from a script still validates; `prompt_rewriter.reasoning_budget` casts it).
- `auto_clip_seconds` (INT, default 15, 5-15): the length of the clips the story planner plans. The planner prompt, the shots-sum check, the planned clips' `duration` and the progress text all use it; 15 is byte-identical to before. Old workflows load with 15.
- **Strata as a rewriter / story-planner writer**: `rewrite_writer_model` gains a last entry, *Strata - Qwen3.8-Flash-Next (local endpoint, 5090)* (`strata_backend.py`). The pack's list only holds GGUF files, so the entry is appended by the extender. It attaches to a Strata already answering on `127.0.0.1:8095` (or `MINIMAX_H3_STRATA_URL`; unloaded, never killed, on release), else starts the GPU gateway's `strata` command on a private port and stops it after the rewrite. Direct to loopback, never through the gateway (its render guard refuses calls made from inside a running job). ComfyUI's models are unloaded first; thinking carries `reasoning_budget_tokens` on every call (4096 when the widget says -1); captions still use the caption model, which is closed before Strata starts. The planner and the clip writers both use it. No widget changes; saved workflows load as before.
- **Story continuity**: the planner now returns an `end_state` for every clip (location, time and light, the exact last action, and each on-screen character's position, wardrobe, props and state). It is written into the clip's raw ask twice: as an `AT THE END OF THIS CLIP` block at its end, and as a `CONTINUITY - THIS CLIP OPENS EXACTLY WHERE CLIP N ENDED` block at the start of the next clip (only when clip N-1 is the planned clip right before it), so the writer of clip N has the exact state clip N-1 closed on in both `raw asks` and `final prompts` mode. A reply without an `end_state` counts as a failed check and gets the planner's one retry. With `final prompts` the writer also gets the last shot of the previous final prompt on its own. The continuity rules sit outside `prompts/planner.md` (the template's "visually self-contained" line is overridden in the message, not edited).
- **Wardrobe from the story, identity from the picture**: reference pictures are captioned as `Identity:` (face, build, skin tone, hair, age, marks) and `Outfit shown:`; captions cached before this are made again once. A Ref2VA writer is told the picture supplies identity only, to put the story's outfit (clip ask, then previous clip's end state, then story, then the picture's outfit only when all are silent) into `subject_definitions`, and to mark the subject `partially_preserved` in `retention_analysis` (identity retained, clothing replaced) without describing the old outfit or naming what is not worn. The planner is told the same (clothing from the story; `as on the reference` when the story is silent).

- **Fix**: the first plan now sees typed clips. With typed clips in the range (1-6 typed and `auto_clips` 10, or clip 1 typed and N=4) only the empty slots are planned, as a continuation of / bridge between the typed clips (`[TO PLAN: clip N]` markers, non-contiguous clip numbers allowed, one call), instead of planning the whole story from scratch and dropping its first clips into the empty slots. One shared context builder serves this and plan-more. With nothing typed the plan is unchanged.
- **Plan more**: raising `auto_clips` past the existing clip count plans only the new clips after the existing ones (continuation block, carried ledger state, numbering from the next clip). The planner's end-of-clip state is stored on each planned clip as `plan_end_state`.
- **Fix**: logging model or user text (an en dash, Devanagari...) raised UnicodeEncodeError on a cp1252 console. Our loggers now pass every record through `ConsoleSafeFilter` (typographic punctuation to ASCII, the rest as \\uXXXX); the panel and the stored clips keep the real Unicode.
- `planner_refs` (images / captions / off, default images): the story planner sees the reference pictures (real image parts on the writer server, or caption lines) with a stage-only-with-these rule kept outside `prompts/planner.md`; videos are captions only.
- **Default rewrite system prompt is now the H3 Prompt Studio builder** (`prompts/builder.md`) when `rewrite_system_prompt` and `rewrite_system_prompt_in` are both empty and the task is Ref2VA. T2VA keeps MiniMax's official guide (the builder is written for ref2va). `@official` in the widget selects the official guide everywhere. Old workflows with an empty system prompt get the builder for clips rewritten from now on; already rewritten clips are kept.
- `auto_clips` (INT, default 0) and the story planner: plan `rewrite_story` once into N 15 s clips (`prompts/planner.md`, run on the writer GGUF), flagged *planned* in the panel; "Replan from story" is the only way to plan again.
- `rewrite_story` (multiline STRING): a film-level story block for every clip's writer.
- `rewrite_previous_clips` gains `final prompts`.
- New inputs are appended last; the trailing JS-only `master_ui` value of older workflows is repaired on load (`auto_clips`).
- Example workflows updated; `Story_Builder` and `Story_Auto` added.
